# 08 — Reasoning-state proxies in interactive Blocks World

This pilot builds and exercises the task generator, symbolic execution wrapper, reference-plan checks, and action/outcome trajectories. The first deterministic reference-controller trajectories validate the environment; an LLM-agent run has now been added. It stops before analyzing action/outcome proxy-states.

## Scope and caveat

The reference trajectory collector uses a deterministic plan controller. The LLM agent is a separate Pydantic AI tool-using agent. It receives the full symbolic state and goal, and can only act through `execute_action`. Its disturbed condition injects a one-time transient failure on a valid action after at least two attempted calls; the model decides what to do next. These runs are observational pilot data, not a powered comparison or a claim about hidden reasoning states.

## Contents

- `pddl/domain.pddl`: copied Blocks World 4-operator STRIPS domain.
- `pddl/tasks/`: 12 generated solvable tasks (5 or 6 blocks; seeds 101–112).
- `lib/pddl_env.py`: PDDL-backed execution wrapper. Each outcome includes action, status, details, state before/after, whether the world changed, goal, and goal status. The full state is observable after every attempted action. `list_available_actions()` returns the full grounded action vocabulary for the task, independent of world state; it does not filter on preconditions. Malformed calls, unknown grounded actions, precondition failures, transient failures, and successful actions have distinct outcomes. Invalid actions leave the world unchanged.
- `scripts/generate_and_validate.py`: generate tasks, solve with Pyperplan A*/hFF, and replay plans through the wrapper.
- `scripts/smoke_test.py`: test wrapper behavior on all tasks.
- `scripts/collect_trajectories.py`: collect matched baseline and single-transient-failure episodes.
- `scripts/run_llm_agent.py`: run the Pydantic AI agent; output contains tool actions/outcomes and states, not chain-of-thought.
- `requirements-agent.txt` and `requirements-agent.lock`: pinned Pydantic AI dependency and resolved environment lock.
- `results/tasks.json`: seeds, task metadata, initial states, goals, reference plans, and lengths.
- `results/trajectories.json`: 24 episodes and complete action-outcome/world-state event histories.
- `results/models/gpt-6-luna/`: trajectories generated by `gpt-6-luna` (the original run and the regenerated action-catalog run).
- `results/models/qwen-qwen3.5-9b/`: trajectories generated by `qwen/qwen3.5-9b`.

Reference plan lengths are not claimed to be optimal. The planner and executor share Pyperplan's PDDL parser/grounded operators, so replay alone is not an independent PDDL validator.

## Reproduction

Prerequisites: Python 3.12, Git, a C/C++ compiler, Make, and a configured Caila API key in `HERMES_CUSTOM_CAILA_IO_API_KEY` for the LLM run. No API key is written to the study files.

From this directory:

```sh
python scripts/bootstrap.py
PYTHONPATH=vendor/pyperplan:lib python scripts/generate_and_validate.py
PYTHONPATH=vendor/pyperplan:lib python scripts/smoke_test.py
PYTHONPATH=vendor/pyperplan:lib python scripts/collect_trajectories.py
uv venv --python /home/tony/.local/python-3.12.13/bin/python3.12 .venv
uv pip install --python .venv/bin/python -r requirements-agent.lock
PYDANTIC_AI_NO_BANNER=1 PYTHONPATH=lib .venv/bin/python scripts/run_llm_agent.py --condition both
```

The LLM runner defaults to model `gpt-6-luna` via the Caila OpenAI-compatible API. Override with `REASONING_STATES_MODEL` or `REASONING_STATES_BASE_URL`. Use `--limit N` for a smaller run. Each episode has a 50-tool-call limit. The agent can call `list_available_actions()` to see every grounded action, including currently infeasible actions. The disturbance episode includes one transient failure on a legal tool action after the first two attempts; the agent is not given a scripted retry.

Bootstrap checks out pinned commits of the external repositories. It fetches VAL as a future independent checker, but does not build it.

## Results from this run

- 12/12 generated tasks were solved by Pyperplan A*/hFF and reference plans replayed to the PDDL goals.
- 60 wrapper smoke checks passed across malformed actions, unknown actions, precondition failures, transient failures, and successful actions. The first four did not change the world.
- 24 episodes were recorded: one baseline and one matched disturbed episode per task; 240 total action events.
- In all 12 pairs, the disturbed episode returned to the baseline continuation after the injected failure and retry, and both reached the goal.
- An independent VAL plan check remains outstanding. VAL source was fetched, but this machine has no `cmake`; no package was installed. Current checks are not a substitute for VAL.
- Original LLM run: 24 episodes, 378 events, 23/24 goals; 11 disturbance injections. It predates the full action catalog.
- Regenerated action-catalog run: 24 episodes, 331 events, 24/24 goals; 10/12 disturbance injections. Tasks 004 and 009 reached their goals in two calls before the injection threshold. Outcomes: 298 successful actions, 23 precondition failures, and 10 transient failures; no unknown actions or runner errors.
- Qwen action-catalog run: 24 episodes, 514 events, 19/24 goals, and 11/12 disturbance injections. Baseline: 10/12 goals, 228 events, with 164 successes, 58 precondition failures, 3 unknown actions, and 3 malformed actions. Disturbed: 9/12 goals, 286 events, with 179 successes, 93 precondition failures, 11 transient failures, 1 unknown action, and 2 malformed actions. Four episodes hit the 50-tool-call limit; these are recorded with `UsageLimitExceeded`, not silently removed.
- Qwen batch-03: 24 episodes, 447 events, 23/24 goals; all 12 disturbance injections occurred. Baseline success 11/12 (task-011 hit the call limit); disturbed success 12/12.
- Qwen batch-04: 24 episodes, 534 events, 24/24 goals; 10/12 disturbance injections occurred because tasks 004 and 009 finished before injection. Two episodes hit the 50-call limit but reached their goals before attempting another call.
- Every adjacent pair of recorded events has consistent states (`previous state` equals `next state_before`). Keep episodes without an injected failure: they document that the goal was reached before a disturbance could occur.
- These are exploratory single rollouts per task/condition, not a powered robustness comparison.

## Limitations and next discussion

This remains a small pilot, not a general robustness evaluation. The LLM sees complete state, goal, and all grounded actions, including currently infeasible ones. Tool outcomes are deterministic except for one injected transient failure. There is one rollout per task/condition, no matched sampling seeds, no skill retrieval, and no proxy-state analysis. Examine the LLM trajectories before deciding what comparisons or state abstractions to run.
